# Campus Incident Reporting App

A Flutter + Firebase mobile app where ALU students report campus problems (water, electricity, facilities, furniture, sanitation, safety) and authorised staff review the reports and update their status.

## Features

### 1. Everyone

- Register and log in with a verified ALU email (Firebase Authentication + email verification).
- Browse all reports.
- Search reports by text.
- Filter reports by category and status.
- Open a report to see:
  - Photo
  - Description
  - Staff response
  - Status timeline
- Press **"Me Too"** to confirm an existing problem instead of filing a duplicate.

### 2. Students

- Submit a report with:
  - Category
  - Title
  - Description
  - Location
  - Optional photo
- Report anonymously (other students will not see the name).
- Delete their own report while it is still **Submitted**.

### 3. Staff

- Dashboard with counts per status.
- A **"Needs Attention"** list.
- Change a report's status:
  - Submitted → In Review → In Progress → Resolved
- Leave a note for students.

### 4. Access Control

- Staff-only screens and actions are hidden from students in the app.
- Access is enforced on the server using Firestore and Storage security rules.

## Architecture

The app is split into layers. Each layer only talks to the next one.

```text
Screens / Widgets (UI)          -> Draw the interface, react to taps
        |
        v
Providers (State)               -> AuthProvider, IncidentProvider (notifyListeners)
        |
        v
Services (Data Access)          -> AuthService, IncidentService (only code that calls Firebase)
        |
        v
Firebase                        -> Auth | Firestore | Storage
```

## Firebase Data Structure

### 1. Users Collection

**Document path:** `users/{uid}`

- `name`: User's name
- `email`: User's email
- `role`: User's role (`student` or `staff`)

### 2. Incidents Collection

**Document path:** `incidents/{incidentId}`

- `title`: Incident title
- `description`: Incident description
- `category`: Incident category
- `location`: Location of the problem
- `status`: Current incident status
- `imageUrl`: URL of the uploaded image
- `reporterId`: ID of the person who submitted the report
- `reporterName`: Name of the reporter
- `anonymous`: Indicates whether the report is anonymous
- `staffNote`: Staff response or note
- `meToo`: List of user IDs confirming the incident
- `createdAt`: Server timestamp

### 3. Firebase Storage

Incident photos are stored in:

```text
incident_photos/<timestamp>.jpg
```

- Images are compressed before uploading.

## User Roles and Permissions

| Action | Student | Staff |
|---|---|---|
| View reports | Yes | Yes |
| Submit a report | Yes | Yes |
| Press "Me Too" | Yes | Yes |
| Delete a report | Own report, only while Submitted | No |
| Change report status | No | Yes |
| Write staff notes | No | Yes |
| Access Staff tab | No | Yes |

### Creating Staff Accounts

- Everyone registers as a student by default.
- To create a staff account:
  1. Open the Firebase Console.
  2. Go to **Firestore Database → users**.
  3. Open the user's document.
  4. Change the `role` field from `student` to `staff`.

## How to Run

### Requirements

- Flutter SDK
- Android/iOS emulator or physical phone
- Firebase project
- Git

### Step 1: Clone the Repository

```bash
git clone https://github.com/Queenu-7/Campus_Incident_Reporting.git
```

### Step 2: Navigate to the Project Folder

```bash
cd Campus_Incident_Reporting
```

### Step 3: Install Dependencies

```bash
flutter pub get
```

### Step 4: Configure Firebase

The repository already contains `firebase_options.dart`, which points to the author's Firebase project.

- If that project is still active, you can skip steps 2-4 of Firebase setup.
- To use your own Firebase project, run:

```bash
flutterfire configure
```

- Select your Firebase project and complete the configuration.

### Step 5: Enable Firebase Services

In the Firebase Console:

1. Enable **Authentication → Email/Password**.
2. Create a **Cloud Firestore** database.
3. Enable **Firebase Storage** (requires the Blaze plan).

### Step 6: Publish Security Rules

- Publish `firestore.rules` in **Firestore → Rules**.
- Publish `storage.rules` in **Storage → Rules**.

### Step 7: Configure Allowed Email Domains

- Open `lib/services/auth_service.dart`.
- Find `allowedDomains`.
- Edit the allowed domains if testing with a different email domain.

### Step 8: Run the Application

Check available devices:

```bash
flutter devices
```

Run the application:

```bash
flutter run -d <device-id>
```

- Replace `<device-id>` with your selected device ID.
- You can also run the application in Chrome for quick previews:

```bash
flutter run -d chrome
```

- The application is primarily designed for Android and iOS.

## Known Limitations

- **Anonymity:** Anonymity is applied in the interface only; the reporter's name is still stored in the document.
- **ALU Domain Check:** The ALU domain check is in the app code (email verification provides the real protection).
- **Staff Roles:** Staff roles are assigned manually in the Firebase Console.
- **Automated Tests:** No automated tests have been implemented yet.
- **Push Notifications:** Push notifications are not yet supported.
- **Firebase Storage:** Requires a billing-enabled Blaze project.

## Conclusion

The Campus Incident Reporting App provides a centralised platform where ALU students can report campus problems and authorised staff can manage and resolve them.

The application uses Flutter, Firebase Authentication, Cloud Firestore, Firebase Storage, and Provider to deliver an organised incident reporting and management system.
